02 · Getting started

Project identity

ExpiryWise is a desktop food inventory and expiry-management application developed as the CSE 2100 Software Development Project I.

The central idea

ExpiryWise allows a user to maintain a personal inventory of food items, record information such as name, category, quantity, storage location, purchase date and expiry date, and then use that information to monitor which foods are safe, approaching expiry, expiring today, or already expired. The application combines inventory management, expiry monitoring, notifications, calendar visualization, shopping-list functionality and basic analytics into one desktop application.

Problem being solved

People can forget what food they have, where it is stored, how much is available, and when individual products expire. ExpiryWise provides a centralized way to record and monitor this information.

Project goal

Build a practical desktop application that demonstrates software development concepts including OOP, GUI development, database persistence, layered architecture, event handling and data visualization.

Why desktop?

The project requirement is a software application rather than a website. Therefore the implementation is centered around JavaFX as a native-style Java desktop GUI framework.

Intended user

A person who wants to maintain a small personal food inventory and receive a clear overview of food quantities, expiry conditions, upcoming expirations and shopping needs.

05 · Environment

Set up from scratch

This walkthrough assumes your PC has never run a Java project before: no JDK, no Maven, and a fresh VS Code. Follow the steps in order — do not skip ahead. Each step ends with something you can verify, so if a step fails you know exactly where you are.

Step 0 — Open a terminal

Operating system How to open it
Windows Press Win + R, type cmd, press Enter. (PowerShell also works.)
macOS Press Cmd + Space, type Terminal, press Enter.
Linux Ctrl + Alt + T, or open your distribution's Terminal app.

First, check whether Java is already present. Type this and press Enter: 

java -version

If you see something like openjdk version "21.x.x", you already have a JDK — skip ahead to Step 4. If you see “command not found”, “not recognized as an internal or external command”, or a version older than 21, continue from Step 1.

Step 1 — Download JDK 21

ExpiryWise targets Java 21. Newer versions usually work, but 21 is the version this project is tested against, so use 21 to avoid surprises.

1
Go to the Adoptium download page Open https://adoptium.net/temurin/releases/?version=21 in your browser. Adoptium Temurin is a free, widely used, production-grade OpenJDK build.
2
Choose the right options Set Operating System to your OS, Architecture to x64 (most PCs) or aarch64 (Apple Silicon / ARM laptops), Package Type to JDK, and Version to 21.
3
Download the installer Pick the installer (not the archive) for your OS: .msi for Windows, .pkg for macOS, or .deb / .rpm for Linux. Save it somewhere you can find again.

Step 2 — Install the JDK

1
Windows Double-click the .msi. Click Next through the wizard. On the Custom Setup screen you will see a tree of features — expand it and make sure these two are enabled: “Set JAVA_HOME variable” and “Add to PATH”. If you miss them, you will have to set them by hand later (Step 4 covers that).
2
macOS Double-click the .pkg and follow the installer. Accept the licence and enter your password when asked. The JDK is installed to /Library/Java/JavaVirtualMachines/.
3
Linux Install the package with your package manager, or extract the archive into /opt/ and remember the full path (for example /opt/jdk-21.0.5). You will need that path in Step 4.

Step 3 — Verify the JDK

Close the terminal completely and open a new one. This is important: a terminal that was already open will not see the new environment variables. 

java -version

Expected output — the exact build number does not matter, only the major version: 

openjdk version "21.0.5" 2024-10-15
OpenJDK Runtime Environment Temurin-21.0.5+11 (build 21.0.5+11-LTS)
OpenJDK 64-Bit Server VM Temurin-21.0.5+11 (build 21.0.5+11-LTS, mixed mode)

Also check the compiler, which is the part that actually builds the project: 

javac -version

If java -version works but javac -version says “not found”, you installed a JRE instead of a JDK. Go back to Step 1 and pick the JDK package type.

Step 4 — Set JAVA_HOME (only if Step 3 failed)

If java -version already printed 21, skip this step entirely. Otherwise the JDK is installed but the system does not know where it is.

1
Find the install path Windows: usually C:\Program Files\Eclipse Adoptium\jdk-21.0.x-hotspot. macOS: run /usr/libexec/java_home -v 21. Linux: /opt/jdk-21.0.x or wherever you extracted it.
2
Windows — set it through the UI Press Win and search for “Edit the system environment variables” → Environment Variables… → under System variables click New… → Variable name JAVA_HOME, Variable value = the JDK folder path (no \bin at the end). Then find Path, click Edit…, add a new entry %JAVA_HOME%\bin, and click OK on every dialog.
3
macOS / Linux — set it in your shell profile Open ~/.zshrc (macOS) or ~/.bashrc (Linux) in a text editor and add the two lines below, then run source ~/.zshrc (or source ~/.bashrc) and reopen the terminal. 
# macOS
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH="$JAVA_HOME/bin:$PATH"

# Linux
export JAVA_HOME=/opt/jdk-21.0.5
export PATH="$JAVA_HOME/bin:$PATH"

Step 5 — Download Maven

Maven is the build tool. It reads pom.xml, downloads the JavaFX and SQLite libraries ExpiryWise needs, compiles the code and starts the application.

1
Open the download page Go to https://maven.apache.org/download.cgi.
2
Download the binary archive Under Files, download Binary zip archive (apache-maven-3.9.x-bin.zip). Avoid the src archive — that is the source code, not the program.

Step 6 — Install Maven

1
Extract it somewhere permanent Windows: extract to C:\Program Files\Apache\maven (avoid folder names with spaces if you can). macOS / Linux: extract to /opt/apache-maven-3.9.x. You should end up with a folder that contains bin, conf and lib.
2
Windows — add it to PATH Same Environment Variables window as before. New system variable MAVEN_HOME = C:\Program Files\Apache\maven. Then edit Path and add %MAVEN_HOME%\bin.
3
macOS / Linux — add it to your shell profile Add the lines below to ~/.zshrc or ~/.bashrc, then source the file and reopen the terminal. 
export MAVEN_HOME=/opt/apache-maven-3.9.9
export PATH="$MAVEN_HOME/bin:$PATH"

Step 7 — Verify Maven

mvn -version

You should see something like:

Apache Maven 3.9.9 (8e8579a9e76f7d015ee5ec7bfcdc97d260186937)
Maven home: /opt/apache-maven-3.9.9
Java version: 21.0.5, vendor: Eclipse Adoptium
Default locale: en_US, platform encoding: UTF-8
OS name: "linux", version: "6.8.0", arch: "amd64", family: "unix"

The critical line is “Java version: 21”. If Maven reports Java 8 or 11 here, Maven is finding a different JDK — go back to Step 4 and fix JAVA_HOME, then reopen the terminal.

Step 8 — Install VS Code

1
Download Go to https://code.visualstudio.com/ and download the installer for your OS. Run it and accept the defaults.
2
Install the Java extension pack Open VS Code, press Ctrl + Shift + X (macOS: Cmd + Shift + X) to open Extensions. Search for “Extension Pack for Java” by Microsoft and click Install. This one pack brings in language support, the debugger, Maven integration and the project manager. Installing it is not optional — without it VS Code will show your Java files as plain text.

Step 9 — Open the project in VS Code

1
Get the project folder onto your machine Either clone it (git clone <repository-url>) or copy the ExpiryWise folder across. Everything you need is inside that one folder.
2
Open the folder, not a single file In VS Code: File → Open Folder… and select the ExpiryWise folder — the one that directly contains pom.xml. Opening a single .java file will not work because VS Code needs the whole Maven project.
3
Wait for the import VS Code will detect the Maven project and start downloading dependencies. A small progress indicator appears in the bottom-right status bar. On a first run this can take 2–5 minutes. Do not close VS Code while it runs.
4
Confirm VS Code is using JDK 21 Press Ctrl + Shift + P (macOS: Cmd + Shift + P), type “Java: Configure Java Runtime” and open it. Under JDK for the project it should list a 21 runtime. If it does not, click the pencil icon and point it at your JDK 21 installation.

Step 10 — Run the application

The reliable way to run a JavaFX project is through Maven, from the terminal — not by clicking a green Run arrow on App.java. Running App.java directly often produces the error “JavaFX runtime components are missing”, because the JavaFX libraries are supplied by Maven rather than by the JDK itself.

1
Open the built-in terminal In VS Code press Ctrl + ` (the backtick key, under Esc) or use Terminal → New Terminal. It opens already inside the project folder.
2
Confirm you are in the right place Run dir on Windows or ls on macOS / Linux. You must see pom.xml and the src folder in the listing. If you do not, cd into the project folder first.
3
Build and launch Run the command below. The first execution downloads the JavaFX runtime and the SQLite JDBC driver, so expect a few minutes and a lot of console output. 
mvn clean javafx:run
4
Watch for the window When the build finishes, a JavaFX window titled ExpiryWise opens on the login screen. That is a successful first run.
5
Subsequent runs are much faster Dependencies are cached, so from now on you can simply use: 
mvn javafx:run

To stop the application, just close the window. To stop a stuck build in the terminal, press Ctrl + C.

08 · Technology

Scene Builder

Scene Builder is a development/design tool, not the application architecture.

It provides a visual way to construct JavaFX interfaces and save those interfaces as FXML. The resulting FXML is then loaded by the JavaFX application. Controllers provide the behaviour.

What it is

Scene Builder is a standalone drag-and-drop editor for JavaFX user interfaces. On the left there is a library of controls (buttons, labels, text fields, tables, charts); in the middle a canvas showing the screen you are building; on the right an inspector for properties, layout constraints and the code/fx:id panel. You never write XML by hand — you drag, drop, resize and configure, and the tool writes the FXML for you.

How it fits the workflow

Scene Builder→ .fxml file→ FXMLLoader→ Controller

What you actually do in it

  • Drag a layout container onto the canvas — VBox, HBox, BorderPane, GridPane — and nest more containers inside it.
  • Drop controls into those containers and set their text, prompt text and preferred size.
  • In the Code panel on the right, give each control an fx:id. That identifier is what lets the controller find the control in Java. A control with no fx:id cannot be reached from code.
  • Set the controller class for the whole file (bottom-left, under Controller). This is the Java class that will receive the events.
  • Attach an onAction handler to a button. The dropdown lists the @FXML methods available in the controller — if your method is missing from the list, the controller class is wrong or the method signature is wrong.
  • Save. The result is an ordinary .fxml text file in src/main/resources/fxml/.

How the controller connects to it

// The fx:id in FXML is "foodNameField"
@FXML
private TextField foodNameField;

@FXML
private void handleSave() {
    String name = foodNameField.getText();   // read what the user typed
}

Practical rules for this project

  • Design in Scene Builder, style in CSS. Do not set colours and fonts inline in the FXML — put them in application.css as style classes so light and dark mode both keep working.
  • Never put SQL or business logic in FXML. FXML describes structure only.
  • If a screen starts refusing to load, open the FXML in Scene Builder and check the controller path and every fx:id first — that is where most "cannot load FXML" errors come from.
  • Scene Builder is optional. Anything it does can be done by editing the FXML directly in VS Code; it is just slower and more error-prone.
09 · Technology

Maven

The problem it solves

A JavaFX application is not one program — it is your code plus a set of external libraries (JavaFX itself, the SQLite JDBC driver, and their own dependencies). Doing that by hand means downloading dozens of JAR files, placing them in the right folders and adding every one of them to the classpath when compiling and when running. It is tedious and breaks the moment you move the project to another machine.

Maven replaces all of that. You describe what you need in one file, and Maven fetches, caches, compiles and runs everything.

The one file that matters: pom.xml

pom.xml (Project Object Model) is the configuration file at the root of the project. It contains three things you should know about: 

// 1. What Java version to compile with
<properties>
    <maven.compiler.release>21</maven.compiler.release>
</properties>

// 2. Which external libraries the project needs
<dependencies>
    <dependency>JavaFX controls, fxml, graphics …</dependency>
    <dependency>org.xerial:sqlite-jdbc</dependency>
</dependencies>

// 3. Which plugins to run (this is what makes "javafx:run" exist)
<plugins>
    <plugin>javafx-maven-plugin</plugin>
</plugins>

If you ever need a new library, you do not download a JAR — you add a <dependency> block with its group id, artifact id and version, and Maven downloads it on the next build.

Where the libraries actually live

Maven keeps a local cache in ~/.m2/repository (Windows: C:\Users\<you>\.m2\repository). The first build fills it; every build after that reads from it. This is why the first mvn clean javafx:run takes minutes and the second takes seconds. If a build behaves strangely, deleting that folder and re-running forces a clean re-download.

The commands you will actually use

Command What it does
mvn clean Deletes the target/ folder so the next build starts fresh.
mvn compile Compiles the Java sources and reports any errors, without launching the app.
mvn clean javafx:run Clean build, then launch the application. Use this the first time.
mvn javafx:run Launch using the already-compiled classes. Use this day to day.
mvn -v / mvn -version Show the Maven version and, importantly, which JDK it is using.

Why we run through Maven instead of the Run button

The JavaFX libraries are declared as Maven dependencies, not as part of the JDK. When you click Run on App.java in the editor, the editor starts the JVM without that library path and JavaFX refuses to start with “JavaFX runtime components are missing”. Running through mvn javafx:run hands the JVM the correct classpath and the correct module configuration, so it works.

10 · Technology

DB Browser for SQLite in detail

DB Browser is a debugging and inspection tool — not part of the shipped application.

End users never see it. It exists so that you, the developer, can look at the database and confirm what the program actually wrote.

Why you need it

ExpiryWise stores everything in a single file called expirywise.db. That file is binary — opening it in a text editor shows garbage. Without a viewer, you are trusting the UI to tell you the truth about persistence, and the UI can lie: a card can disappear from the screen while the row is still in the database, or a row can appear to save while the INSERT never actually executed. DB Browser settles those questions in seconds.

Getting it

Download from https://sqlitebrowser.org/ and install it like any normal application. It is free and open source. There is nothing to configure.

Opening the project database

1
Run the application once If expirywise.db does not exist yet, it is created on first launch by DatabaseManager.
2
Open the file In DB Browser: Open Database → navigate to the project root → select expirywise.db.
3
Browse the data Go to the Browse Data tab and choose the foods table. You will see the rows, matching the columns in section 16.
4
Run a query if you want The Execute SQL tab lets you type plain SQL against the real database. 
-- See everything in the inventory
SELECT * FROM foods;

-- Find foods that already expired
SELECT name, expiry_date FROM foods
WHERE expiry_date < date('now')
ORDER BY expiry_date;

-- Confirm a delete really happened
SELECT COUNT(*) FROM foods;

The checks it is genuinely useful for

  • “Did the add actually save?” Add a food in the app, switch to DB Browser, hit Refresh — the new row should be there.
  • “Did the delete really delete?” Delete a food, refresh, the row should be gone. If it is still there, the DAO built the statement but never called executeUpdate().
  • “Did the edit persist?” Edit a record, refresh, check the changed column.
  • “Are the analytics honest?” Compare the chart totals with SELECT COUNT(*) grouped by category.
  • “Are favourites stored correctly?” Check that is_favorite flips between 0 and 1.
One rule: back up before you edit by hand.

DB Browser lets you change rows directly, and there is no undo. If you are going to experiment, copy expirywise.db to expirywise.backup.db first. Also close the running application before editing, or SQLite may lock the file.

11 · Architecture

How the application is organized

ExpiryWise uses a layered architecture with MVC-style separation between the interface and the application's data and business layers.

User→ JavaFX UI→ Controller→ Service→ DAO→ JDBC→ SQLite

Model

Represents application data. The central example is Food.java, which represents a food item and its properties.

  • Stores food attributes.
  • Provides getters/setters or equivalent access.
  • Acts as an object representation of database data.

View

The visual part of the application. ExpiryWise primarily uses FXML files to define the UI.

  • login.fxml
  • dashboard.fxml
  • food-dialog.fxml
  • edit-food.fxml

Controller

Connects the interface to application logic. Controllers respond to button clicks, input changes and other UI events.

  • Reads values from UI controls.
  • Calls services.
  • Updates the UI.

Service

Contains application-level business logic instead of directly mixing business rules with UI code.

  • Food retrieval.
  • Expiry-status determination.
  • Application-level operations.

DAO

Data Access Object classes isolate SQL and database operations from the rest of the application.

  • Create records.
  • Read records.
  • Update records.
  • Delete records.

Database layer

DatabaseManager handles database initialization and provides the JDBC/SQLite connection foundation.

The rule of thumb

If you are changing how something looks, it is FXML or CSS. If you are changing what happens when someone clicks, it is a controller. If you are changing a rule, it is a service. If you are changing a query, it is a DAO.

13 · Architecture

What happens when ExpiryWise starts?

1 · Java launches App

App.java extends JavaFX Application and the main method calls launch().

2 · Database initializes

DatabaseManager.initializeDatabase() makes sure the SQLite database and required table structure are available.

3 · FXML is loaded

FXMLLoader loads /fxml/login.fxml and creates the JavaFX scene graph.

4 · Stage is shown

The stage receives the scene, the application title is set, and the login screen becomes visible.

DatabaseManager.initializeDatabase();

FXMLLoader loader = new FXMLLoader(
        getClass().getResource("/fxml/login.fxml"));

Parent root = loader.load();

Scene scene = new Scene(root);

stage.setTitle("ExpiryWise");
stage.setScene(scene);
stage.setResizable(false);
stage.show();
14 · Architecture

How information moves through ExpiryWise

Add food flow

User enters information → food dialog controller reads fields → service/application logic → DAO → JDBC → SQLite → dashboard reloads data.

Edit food flow

Existing Food object → edit screen → user changes values → controller → service/DAO → UPDATE query → SQLite → refreshed UI.

Delete flow

User selects delete → confirmation alert → controller → DAO → DELETE query → executeUpdate() → database changes → UI refresh.

Analytics flow

FoodService retrieves records → controller calculates category/status counts → JavaFX chart components receive the resulting data.

Calendar flow

FoodService provides food records → controller examines expiry dates → matching calendar dates receive status indicators → user clicks a date → matching foods are displayed.

Notification flow

Food data + expiry status → NotificationsController → notification card → title + description + date + status badge.

15 · Architecture

Where should code go?

This is one of the most important concepts for anyone contributing to the project.

If you want to… Primarily look at… Why
Change UI layout FXML / Scene Builder The view structure belongs here.
Change colors or spacing JavaFX CSS Visual styling should not be scattered through controller code.
Handle a button click Controller Controllers handle UI events.
Change expiry/business logic FoodService Business rules belong in the service layer.
Change SQL DAO Database queries belong in the data-access layer.
Change database initialization DatabaseManager Database creation and connection responsibilities live here.
Add a food property Food.java + database + DAO + UI The property must exist consistently across the data flow.
Add a new screen FXML + Controller + CSS/resources JavaFX screens are split between view and controller.
16 · Database

SQLite data model

Food data is stored locally in the SQLite database file expirywise.db. Database URL: jdbc:sqlite:expirywise.db.

Column Type Purpose
id INTEGER Primary key and unique identifier for each food item.
name TEXT Name of the food. Required.
category TEXT Food category.
quantity TEXT User-defined quantity information.
purchase_date TEXT Date the food was purchased.
expiry_date TEXT Food expiry date. Required.
location TEXT Storage location.
is_favorite INTEGER Stores favorite state, using an integer representation.
image TEXT Path/reference associated with the food image. 
CREATE TABLE IF NOT EXISTS foods (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    category TEXT,
    quantity TEXT,
    purchase_date TEXT,
    expiry_date TEXT NOT NULL,
    location TEXT,
    is_favorite INTEGER DEFAULT 0,
    image TEXT
);

23 · Features

Expiry status system

Expiry status is a core piece of ExpiryWise's business logic.

Safe

The food is not currently in the application's warning conditions.

Use soon

The food is approaching its expiry date and should receive attention.

Expires today

The stored expiry date corresponds to the current date.

Expired

The expiry date has already passed.

Where should this logic live?

The important architectural principle is that expiry classification is application/business logic and therefore belongs in FoodService rather than being duplicated independently inside every UI screen.

30 · Learning

What to learn, and in what order

You do not need to master everything before opening the project. Learn the concepts in dependency order — each phase below only uses things you learned in the phases before it.

Three rules for this roadmap

1. Do not skip ahead. Trying to learn JDBC before you are comfortable with Java classes will just be frustrating. 2. Write code after every phase. Reading about JavaFX for three hours teaches you less than making one button work. 3. Learn just enough to unblock yourself. You are not trying to become a Java expert — you are trying to understand this project.

A class is a blueprint; an object is one thing made from it. Food.java is a class; each food you add is an object. Learn fields, constructors, getters/setters, encapsulation, static and final.
